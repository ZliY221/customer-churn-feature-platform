# 用户使用指南

适用版本：`v3.4.0`

本指南随项目版本同步更新，覆盖当前版本的数据链路、模型监控和留存运营流程。首次使用建议先阅读仓库首页的项目简介、业务流程和常用入口，再按本指南启动完整链路。

## 1. 环境要求

- Python 3.11 或更高版本
- 本地完整演示无需外部数据库，运营任务使用 SQLite 保存

建模环境和 API 运营环境分开检查，具体命令见[运行环境分层](runtime-environments.md)。启动器使用项目专属依赖目录，并固定 UTF-8 子进程输出以适配中文路径。

## 2. 最快启动

在仓库根目录执行：

```powershell
python scripts/bootstrap.py
```

该入口会创建隔离运行时，生成匿名行为事件，构建时间点特征，训练基线与挑战者模型，运行批量推理、漂移监控、性能监控和模型比较。输出位于 `build/quickstart/`。

## 3. 启动运营工作台

先完成最快启动，再执行：

```powershell
./scripts/api-up.ps1
```

访问 `http://127.0.0.1:8000/console`。工作台提供客户组合概览、风险分层、高风险优先队列、留存任务和处置结果看板。v3.0.0 延续客户成功工作台版型，并将“完成闭环”扩展为可登记联系与留存观察结果的实际操作入口。

## 4. 留存任务

`GET /v3/retention/outcomes/by-strategy` 会按执行策略比较已成熟的 7 天与 30 天留存率；尚未填写对应观察结果的数据不会进入分母，避免把等待观察的任务误判为流失。

SLA 概览按配置的响应小时数区分正常、4 小时内临期和已超时任务；`GET /v3/retention/sla?target_hours=24` 可用于值班看板和协作交接。

策略概览会按任务使用的执行策略汇总任务数、完成数与高优先级客户数，可通过 `GET /v3/retention/strategies` 读取，用于比较电话、消息等不同跟进方式的当前工作量。

在优先队列中选择客户并创建任务，填写负责人和执行策略。任务支持以下状态：

- `OPEN`：待执行
- `IN_PROGRESS`：处理中
- `COMPLETED`：已完成
- `DISMISSED`：已关闭

每次创建和状态变更都会写入独立事件流水。工作台每 2 秒使用事件游标检查新增变更；其他浏览器创建任务或更新状态后，当前页面会自动刷新责任负载与任务看板。工作台显示累计变更记录数；点击任务卡片中的“查看时间线”可以直接查看创建时间和历次状态流转。任务看板支持按风险等级和负责人组合筛选。“负责人任务负载”区域汇总每位负责人的活跃任务、待执行、处理中、极高风险和高风险数量，便于平衡任务分配。

需要调整一组任务时，勾选任务卡片、输入新的负责人并点击“批量分派”。接口会先确认全部任务存在，再在同一事务内完成更新；每条发生变化的任务都会新增负责人变更事件，并通过事件游标同步到其他在线工作台。

勾选多条任务后还可以点击“批量开始”或“批量完成”，统一推进任务状态。每次批量分派或状态推进都会先读取预览，显示将更新、将跳过的数量以及受影响任务的风险等级分布；预览同时返回每条变化任务的任务编号、风险等级、变化字段以及负责人和状态的变更前后值。工作台确认框展示前三条明细，其余任务显示剩余数量，方便在执行前核对影响范围。负责人仅包含空格时，预览和正式执行都会拒绝，避免确认结果与实际执行不一致。确认后才执行，取消则不会改写任务。系统会先校验全部任务，再进行事务化更新；重复设置为当前状态不会产生多余审计事件。组合操作完成后会返回逐任务实际变化清单和字段总数，并生成 `RET-` 开头的短回执编号；重复执行时变化清单为空，便于核对预览、最终执行结果和审计事件范围。

任务卡片中的负责人可以直接修改并点击“分派”。负责人变化会写入任务时间线，并通过实时同步更新其他在线页面的任务卡片与责任负载。

新版工作台提供“分派并开始”：输入负责人、勾选任务并确认预览后，系统在同一事务中同时更新负责人和状态。任意任务不存在或输入不合法时整批不执行；每个实际变化字段仍分别写入负责人和状态事件，重复执行不会新增事件。

预览会对三类操作显示重点确认原因：包含极高或高风险任务、推进到已完成或已关闭终态、同时修改负责人和状态。确认框会显示标准化原因，便于在真正执行前再次核对。

影响摘要同时返回实际变化字段数、变化任务涉及的原负责人数量，以及目标负责人和目标状态。字段变化数可能大于任务数，例如“分派并开始”对一条任务会产生两个字段变化。

组合执行回执包含本次新增审计事件数、首个新事件编号和最新事件编号。工作台会显示新增事件数；重复执行没有实际变化时新增数为 0，可据此核对实时事件游标是否完整推进。分派并开始前可填写操作备注，接口通过 `operator_note` 接收并在 `audit` 中原样返回，用于说明本次批量操作的业务背景。`selection` 会区分输入任务数、唯一任务数和重复选择数。`impact.risk_band_counts` 按四档风险返回实际任务分布，`high_priority_count` 汇总极高风险和高风险任务。`follow_up` 会根据实际变更和风险影响给出下一步动作与优先级：高优先级客户标记 P1 并在 4 小时内跟进，其他已变更任务标记 P2 并在 24 小时内复核，无变化时返回 `NONE` 和选择检查提示。`handoff.summary` 将回执、影响任务数、高优先级数量、目标负责人和后续动作整理成一行，`handoff.checklist` 给出审计核对、负责人联系和复核安排步骤；`step_count` 与 `estimated_minutes` 用于在执行前评估交接规模。`readiness` 区分可跟进、需升级和需重新检查选择，`blockers` 提供具体阻塞原因。

任务开始跟进后，点击任务卡片中的“登记结果”。选择联系渠道和联系结果，填写客户反馈与联系时间；达到观察窗口后再补充 7 天或 30 天是否留存。重复保存会更新同一条结果记录，不会创建多个相互冲突的结果。每次保存都会在任务时间线中增加“登记处置结果”事件。“留存处置结果”区域只使用已到观察窗口且已填写结果的记录计算留存率，尚未成熟的数据不会进入分母。

## 5. 主要接口

- `GET /health`：模型与预测批次就绪状态。
- `GET /v1/portfolio/summary`：客户组合、风险与任务汇总。
- `GET /v1/portfolio/priority`：按风险等级读取运营优先队列。
- `POST /v1/retention/tasks`：创建留存任务。
- `GET /v1/retention/tasks?risk_band=HIGH&owner=retention-team`：按风险与负责人筛选任务。
- `GET /v1/retention/workloads`：查看负责人活跃任务与风险负载。
- `GET /v1/retention/events?after_id=0`：按事件编号增量读取任务创建和状态变更。
- `PATCH /v1/retention/tasks/{task_id}/status`：更新任务状态。
- `PATCH /v1/retention/tasks/{task_id}/owner`：重新分派任务负责人。
- `PATCH /v1/retention/tasks/bulk-owner`：批量重新分派负责人。
- `PATCH /v1/retention/tasks/bulk-status`：批量推进任务状态。
- `POST /v1/retention/tasks/bulk-preview`：只读预览批量分派或状态推进影响，并返回逐任务前后值。
- `PATCH /v2/retention/tasks/bulk`：在同一事务中组合执行负责人和状态变更。
- `GET /v1/retention/tasks/{task_id}/events`：查询任务事件流水。
- `PUT /v3/retention/tasks/{task_id}/outcome`：创建或更新任务联系与留存观察结果。
- `GET /v3/retention/tasks/{task_id}/outcome`：读取单个任务的处置结果。
- `GET /v3/retention/outcomes`：读取已登记的任务结果。
- `GET /v3/retention/outcomes/summary`：读取联系数量和 7/30 天留存率汇总。

接口文档位于 `http://127.0.0.1:8000/docs`。

## 6. 模型与数据监控

`GET /v3/retention/outcomes/by-model-risk` 将模型 SHA-256、风险档位和 30 天实际留存结果关联起来，便于比较不同模型批次在各风险层的业务效果，同时保留完整模型血缘。

完整演示会输出特征漂移、预测分布漂移、延迟标签效果和 Champion/Challenger 对比报告。报告只保存聚合指标、模型摘要和匿名键，不输出客户直接身份信息。

## 7. 工程验证

```powershell
./scripts/test-all.ps1
```

统一入口覆盖特征快照、训练与推理、漂移和效果监控、接口、运营任务以及仓库发布内容。Windows 会自动选择可用的 Python 3.11 运行时，避免系统占位命令中断验证。

## 8. 常见问题

- API 提示模型文件不存在：先执行 `python scripts/bootstrap.py`。
- 任务数据库需要切换位置：通过 `CHURN_TASK_DATABASE_PATH` 指定 SQLite 文件。
- 重复创建任务返回冲突：同一预测只允许一个留存任务，可在任务看板继续更新状态。
- 页面没有最新数据：查看页头实时同步状态，或检查 `/health` 与浏览器网络请求。

## 9. 数据边界

`GET /v3/retention/priority-queue` 按风险等级和任务创建时间生成待联系队列，并返回可读的排序原因。运营人员可使用 `limit` 控制本次领取数量，已完成或已忽略任务不会进入队列。

仓库样例全部为匿名合成数据。特征按 `as_of_time` 构建，未来事件只用于生成延迟标签，不进入当期特征。模型文件、预测批次和任务库均保留可追溯标识。
