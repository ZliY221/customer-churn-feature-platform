# 特征注册表与离线/在线一致性核对

## 设计范围

特征注册表为训练、批量推理和在线查询提供同一份特征契约。当前版本关注定义一致性和结果核对，不实现独立的在线特征存储服务。

## 注册表契约

`config/feature-registry.json` 保存：

- 注册表语义版本和规范化 SHA-256；
- 实体键 `customer_key` 与时间键 `as_of_time`；
- 责任团队；
- 十项模型特征的固定顺序、数值类型、在线能力和业务说明。

加载器要求注册表中的特征顺序与模型 `FEATURE_COLUMNS` 完全一致，并拒绝重复名称、未知类型和不完整定义。这样可以在模型加载前发现训练与服务契约分叉。

## 一致性核对

核对工具分别以实体键和时间键索引离线、在线快照，并输出：

- 离线存在但在线缺失的实体数；
- 在线额外出现的实体数；
- 每项特征的差异单元格数；
- 两侧行数和匹配实体数；
- 注册表版本与指纹。

整数特征精确比较；金额等小数特征使用默认 `0.000001` 的显式容差。输入中的重复实体时间点、缺失特征或不合法数值会直接中止核对。

## 隐私边界

报告不保存 `customer_key`。缺失、额外和差异样例只保存 `customer_key:as_of_time` 的 SHA-256 前 16 位，并限制最多 20 个样例。报告可定位特征类型和批次范围，但不能从中恢复实体标识。

## 查询接口

```http
GET /v1/features
```

接口返回注册表版本、指纹、实体与时间键、责任团队及特征定义。模型元数据接口继续返回实际训练使用的特征列，两者可独立比对。

## 功能边界

一致性核对证明两份指定快照在注册特征上的结果关系，不证明在线服务延迟、缓存命中率或长期稳定性。生产环境应将报告接入发布门禁，并为在线特征写入增加独立的新鲜度和可用性监控。
